# Jeff Windows Lab

**Архивный изолированный fixture для регрессии.** Основной ярлык и `npm run lab` теперь открывают [реальное управление Windows](windows-desktop.md). Описание ниже относится только к `lab:fixture`.

Отдельный исследовательский стенд на Electron + C# + FlaUI.UIA3 5.0.0. Модель Jev выбирает действия по настоящим наблюдениям Windows UI Automation; между шагами Codex не читает экран и не выбирает кнопки. Это проверка механизма в собственном тестовом окне, не универсальный ассистент всех приложений.

## Запуск

```powershell
npm.cmd run lab:build
npm.cmd run lab:fixture
```

Первый шаг компилирует два небольших EXE средствами установленного .NET Framework 4.8, загружает официальные NuGet-пакеты с зафиксированными версиями и проверяет SHA-256. Глобальный .NET SDK не требуется. Повторная сборка не нужна до изменения native-кода. Для запросов нужен настроенный TypeSafe DPAPI-файл этого проекта либо `TYPESAFE_API_KEY`.

1. Написать свою команду в поле ввода либо выбрать пример, который тоже можно отредактировать.
2. Нажать «Выполнить». Белое окно **Jeff Desktop Lab Target** — само тестовое приложение. Оно автоматически открывается, а если свёрнуто — восстанавливается. Постоянно держать его открытым не нужно; закрытое окно будет создано заново с начальным состоянием.
3. Посмотреть распознанную цель, ход выполнения и проверенный результат. Кнопка «Журнал» показывает последние 20 сессий; выбранная запись раскрывает полный JSON.
4. «Reset lab» в тестовом окне возвращает начальное состояние. «Стоп» отменяет будущие шаги, но не откатывает уже сделанное.

Примеры ручного ввода: «Включи музыку в тестовом окне», «Поставь воспроизведение на паузу», «Выбери русский язык внутри тестового окна», «Открой вкладку Music и выбери русский язык», «Открой вторую вкладку ВК», «Сбрось тестовое окно».

Свободная формулировка действует **только в пределах песочницы**: четыре вкладки Documentation/VK feed/Music/VK video, состояние воспроизведения и тестовый язык English/Russian. Команды реальным приложениям, таймеры, условия и временные последовательности с повторным изменением одного поля здесь не поддерживаются. Смешанный запрос «Открой Chrome и включи музыку» должен целиком остановиться. Вероятностная интерпретация может ошибиться; результат распознанной цели и все вероятности видны в журнале.

Стенд не включает микрофон, не открывает сайты, не проигрывает звук и не меняет установленный Assistant Jeff. Английский/русский переключатель в тестовом окне — локальный mock, не раскладка Windows. Закрытие стенда завершает только созданные им два процесса. «Стоп» прерывает цикл; уже выполненный шаг не откатывается.

## Как он принимает решение

```text
ручная команда
    → Jev определяет запрошенные поля и желаемые конечные состояния
    → код проверяет закрытую схему цели и пороги
    → FlaUI читает текущее окно и UIA patterns
    → код строит кандидаты из доступных элементов
    → Jev выбирает один id или done/unsupported
    → код проверяет порог и свежесть состояния
    → UIA SelectionItem/Invoke выполняет действие
    → новое UIA-наблюдение проверяет результат
    → при необходимости следующий шаг
```

Порог цели и действия — probability ≥0.80 и confidence ≥0.80. Confidence получен из того же распределения, а не от независимой проверяющей модели. Максимум восемь шагов и 60 секунд на задачу, 12 секунд на ответ модели. Неоднозначный ответ, неизвестный id, неподтверждённый эффект или устаревший снимок не считаются успехом. Уже достигнутая цель после её распознавания не требует исполнительных действий.

В C# нет интерпретатора естественного языка и прописанных последовательностей «команда → клики». C# читает подписи, порядок, доступность и patterns. Jev предлагает цель вида `{selectedTab?, playing?, language?}` и по свежим наблюдениям выбирает следующие действия. Код проверяет фактическое совпадение UIA-полей с этой целью; правильность интерпретации исходной фразы остаётся модельной оценкой. Helper привязан к собственному EXE/PID/session/start-time и не принимает произвольное имя приложения, координаты, текст или shell-команду.

Структура входа — `state: {command, observation, candidates, completed}` плюс `questions.next_action.instructions/criteria`. Выход — выбранный id, probability, confidence и usage. В UI есть полная трассировка; JSON отчёты лежат в игнорируемой Git папке `work/desktop-lab/runs/`. Стенд сохраняет точный JSON request без headers, а из response — model, answers и usage до нормализации. Ключи и HTTP Authorization не сохраняются.

## Журнал и восстановление окна

Каждая задача получает runId. В `work/desktop-lab/runs/<runId>.jsonl` события дописываются сразу: подготовка окна, UIA-наблюдения, запрос/ответ компилятора цели, план, запросы/ответы выбора действия, вероятности, проверки свежести, запрос и результат native-действия, проверка результата, причина остановки и времена. Запись запроса действия завершается **до** его исполнения. Полный итог сохраняется в соседний `.json`. Ключи и Authorization исключены/редактируются. Журнал содержит введённые команды; он локальный и не входит в Git.

При закрытии процесса до завершения JSONL позволяет прочитать записанную часть. История помечает такой запуск как прерванный и не повторяет его автоматически. Это не гарантия сохранности при потере питания: принудительный fsync не используется.

`TARGET_SURFACE_MISSING` был воспроизведён на свёрнутом WinForms-окне. Теперь обычное чтение возвращает `TARGET_WINDOW_MINIMIZED`, а явный Start/Run вызывает новый `prepare`, который восстанавливает только привязанный fixture через UIA WindowPattern. Закрытый процесс controller запускает заново. Фоновое чтение не поднимает окна самостоятельно; при ошибке старый снимок не показывается как свежий.

## Исторический прогон двух фиксированных команд, 20 сентября

### Последующее обновление: ручной ввод и журнал

Проверка через настоящий Electron renderer/IPC/TypeSafe/UIA (`work/desktop-lab/ui-smoke-2026-09-19T21-59-38-868Z`) дала:

| Ручная команда | Результат | Полное время |
|---|---|---:|
| Включи музыку в тестовом окне | Music → Play, playing=true | 12 851 мс |
| Выбери русский язык внутри тестового окна | language=Russian | 6320 мс |
| Поставь воспроизведение на паузу | playing=false | 7288 мс |
| Объясни, что означает «включи музыку» | no_request, 0 действий | 2396 мс |
| Открой Chrome и включи музыку | goal_low_confidence, 0 действий | 2178 мс |

У последнего запроса модель ошибочно предпочла execute (P=0.58/confidence=0.44) вместо unsupported; защитил порог, а не верная категоризация. Сохранённый smoke имеет `passed:false`, потому что тогда ожидал точный label unsupported. После уточнения теста допустим безопасный отказ goal_low_confidence; исходный артефакт не переписывался, API повторно ради зелёного статуса не запускался. Все три положительные команды и обе проверки отсутствия эффектов подтверждены отчётами; чтение истории и полного JSON через интерфейс также прошло.

До этого были два отладочных прогона: первый блокировал положительные команды из-за неуверенных keep-ответов для незапрошенных полей; второй выявил смешение конечной цели и промежуточной навигации. Добавлена независимая маска requested_fields и уточнены её критерии. Используемые ветки по-прежнему требуют P/confidence ≥0.80. Это исправления по наблюдавшимся примерам, не независимая оценка точности. Старые отказы остались в журнале.

Обнаружена и устранена гонка renderer: поздний progress мог заменить готовый отчёт промежуточным JSON во время финального refresh. Теперь финальный отчёт защищён флагом завершения и runId. 99 автоматических тестов прошли, один внешний wake-word oracle пропущен.

### Предыдущая версия с двумя пресетами

Последний сквозной тест прошёл через настоящий Electron renderer → IPC → C# UIA helper → API Jev. Каталог `work/desktop-lab/ui-smoke-2026-09-19T21-39-02-886Z/`, модель ответила `jev-1.13.0`. Общий тест **не прошёл полностью: 1 из 2 задач выполнена**, второй отказ корректно сохранён.

| Задача | Фактический результат | Jev | Полный цикл |
|---|---|---|---:|
| Первая вкладка ВКонтакте | Правильный VK feed выбран, действие заблокировано | P=0.75, confidence=0.71; 950 мс | 1399 мс, без эффектов |
| Включить воспроизведение | Сам выбрал Music, затем обнаруженный Play; UIA подтвердил оба шага | P=0.96/0.99, confidence=0.96/0.99; 293/357 мс | 8069 мс |

Таким образом, 0.3 секунды на ответ модели не означают такую же задержку команды. Отдельный native-прогон без API дал первый snapshot за 915 мс, повторные observe за 405–700 мс, execute select за 1619 мс, execute invoke за 1058 мс. Execute включает проверки и повторные обходы дерева; чистое время pattern отдельно не выделено. Следующий шаг оптимизации — убрать дублирующие обходы, сохранив проверку свежести и результата.

История интеграционной отладки сохранена, не считается независимой оценкой точности:

- Первый запуск исходной общей инструкции: правильный VK feed, P=0.59/confidence=0.53, no_action (`work/desktop-lab/ui-smoke/`).
- После замены общей инструкции на неизменённый detailed из A/B: один `dependency_error` без сохранённого payload, причина не установлена (`ui-smoke-2026-09-19T21-36-33-703Z`). Затем добавлено диагностическое сохранение ответа и кода ошибки.
- Следующий запуск: правильный VK feed, P=0.61/confidence=0.55, no_action (`ui-smoke-2026-09-19T21-37-33-338Z`). Подробный prompt сам проблему не решил.
- Observer стал явно указывать наблюдаемую группу вкладок и исключать no-op выбора уже активной вкладки. Финальный прогон выше дал P=0.75. Имена целей и команды не менялись; ответа в prompt нет. Это последовательная разработка на знакомом примере, не A/B доказательство роста точности.
- Отдельный music-only прогон до последней корректировки observer тоже прошёл: 8187 мс, модель 967/326 мс, P=0.98/0.99.

Порог ниже 0.80 не опускался. 83 автоматических теста прошли, один сравнительный тест wake-word с внешним Python-эталоном пропущен; это отдельно от частично успешного живого UI-теста. Поддержка двух мониторов не проверялась: helper только сообщил их количество.

## Исследование и следующий этап

[Сравнение готовых Windows-инструментов](windows-tools-research.md): FlaUI, Microsoft winapp CLI, Windows-MCP, UFO и другие. В стенде используется FlaUI; пригодность альтернатив по README не выдаётся за локальный тест.

[Сравнение инструкций Jev](jev-prompting.md): 40 реальных запросов на фиксированных синтетических данных. Короткий профиль — 18/20 правильных labels; подробный — 20/20. Ошибочных разрешённых действий не было у обоих. Пороги 0.80 и 0.85 дали одинаковый результат на этой выборке. Это малая проверка, не общая оценка точности модели.

Для дальнейшего управления приложениями нужен более общий observer с выбором окна, отдельные исполняемые patterns и проверяемая спецификация цели. UIA не гарантирует доступность каждого элемента: виртуализированные списки, canvas, браузерные вкладки и смешанный DPI проверяются отдельно. Для браузера возможен отдельный канал через разрешённое расширение/API. Постоянно пересылать модели весь рабочий стол не требуется: компактное наблюдение читается по шагам активной задачи.

Полный голосовой цикл, универсальный разбор целей для произвольных приложений, реальный Яндекс/Музыка и работа двух мониторов не подтверждаются этим стендом.
