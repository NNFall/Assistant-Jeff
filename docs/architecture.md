# Архитектура Assistant Jeff 0.5

Документ описывает основной путь в исходниках версии 0.5.0. Он не подтверждает установку этой версии, публикацию установщика или состояние удалённой ветки. Исторический Electron-путь 0.2 доступен через `npm run start:legacy`, Python-прототип сохранён отдельно.

## Контур выполнения

```text
scripts/desktop-lab/lab.js + VoiceClient
        ├─ введённая задача ──────────────────────────────┐
        └─ микрофон → PCM16 mono 16 kHz, кадры 80 мс      │
                   ↓ узкий IPC                           │
scripts/desktop-lab/main.mjs → VoiceSession               │
        ↓ локальное ожидание Hey Jarvis / ручная запись   │
BatchVoiceController: одна активированная реплика          │
        ├─ live: PCM + буфер подключения → Gemini Live    │
        └─ batch: готовая запись → FFmpeg MP3 → Gemini     │
        ↓ только финальный текст                         │
UnifiedCommands ←────────────────────────────────────────┘
        ↓ Jev: типизированный маршрут и аргументы
        ├─ исходный текст заметки / срок → SQLite Store
        ├─ недостающее время → уточнение
        ├─ громкость → Windows CoreAudio + readback
        ├─ свернуть Jeff → callback собственного окна
        ├─ WindowsDesktop → Jev action choice → Win32/UIA
        └─ вопрос → Gemini chat без инструментов компьютера
        ↓ отчёт с доказательствами результата
Интерфейс + журнал + локальный Piper/Денис
```

Точка входа `package.json` — `scripts/desktop-lab/main.mjs`. Она связывает окно, трей, SQLite, разрешение микрофона, IPC, провайдеры и исполнителей. Несмотря на имя каталога, это основной интерфейс. Renderer изолирован через `contextIsolation`, sandbox и отключённую Node integration; доступен ограниченный preload API. Переходы и новые окна блокируются. Команды моделей не становятся shell-кодом.

## Голос и граница выполнения

`scripts/desktop-lab/voice-client.mjs` управляет захватом и воспроизведением в renderer. `desktop/audio/session.mjs` объединяет текстовые и голосовые задачи, связывает результат с операцией и отправляет его в интерфейс до озвучки. Текстовая задача не включает микрофон.

`desktop/audio/batch-controller.mjs` сохраняет своё имя, но обслуживает оба режима. По умолчанию `settings.transcriptionMode` равен `live`; значение `batch` соответствует настройке «После записи». Ожидание имени работает локально через ONNX openWakeWord. Облачное соединение для аудио открывается только после wake-активации или ручного начала записи.

Запись начинается сразу при активации, параллельно с подключением. Ограниченный локальный pre-roll и очередь PCM сохраняют начало реплики, пока соединение готовится. Одна реплика ограничена 30 секундами; тишина после речи по умолчанию завершает запись через 2000 мс. Отсутствие речи обрабатывается отдельно. Кнопка «Завершить запись» завершает ввод раньше.

В live-режиме `desktop/providers/gemini-live.mjs` передаёт PCM16LE 16 kHz через защищённый туннель в `server/gemini-live.mjs`. Шлюз работает с `gemini-3.5-transcribe-live`. Промежуточные события имеют `final:false`: UI показывает их отдельной подписью, не записывает в поле исполняемой команды и не вызывает исполнителя.

После локального окончания речи отправляется конец аудио. Шлюз ждёт финализированную входную транскрипцию и `generationComplete`, полученные после этого окончания; порядок этих двух событий не важен. До выполнения условия итоговый `result` не выдаётся. Клиент принимает результат только после отправки конца ввода. Пустой, слишком длинный, запоздалый или отменённый результат не запускает задачу. Это защита от преждевременного выполнения, а не оценка правильности распознанных слов.

В batch-режиме готовая запись кодируется FFmpeg в MP3 и передаётся `/transcribe` для `gemini-3.5-transcribe`. Резервный режим выбирается в настройках; ошибка live не запускает скрытую повторную отправку той же команды. AssemblyAI и SAPI не участвуют в основном пути 0.5.

Основные состояния: `stopped`, `waiting`, `recording`, `transcribing`, `ready`, `processing`, `speaking`, `error`; UI также показывает подготовку микрофона. `stream_status` с `connecting`, `live`, `finalizing` уточняет фазу распознавания. Stop меняет поколение сессии, отменяет дальнейшую обработку и проигрывание; поздние события старой операции отбрасываются. Уже выполненные действия не откатываются. При выключенном автовыполнении финальный текст остаётся для проверки, захват останавливается.

Озвучка использует `desktop/audio/denis.mjs`, нативный Piper и модель Denis. `desktop/automation/feedback.mjs` формирует общий текст результата и короткую голосовую реплику: неподтверждённое действие не объявляется успехом, перед повтором предлагается проверить приложение. Во время ответа новая голосовая команда не исполняется. Chromium запрашивает echo cancellation и noise suppression, но это не доказательство качества AEC; приглушение других приложений в основном пути не подключено.

## Jev: смысл запроса и исходные аргументы

`UnifiedCommands` из `desktop/automation/assistant-commands.mjs` получает финальную команду и вызывает `desktop/providers/assistant-intent.mjs`. Адаптер использует `/v1/systemone` с alias `jev-latest`. Маршруты: `note`, `reminder`, `system_volume`, `self_minimize`, `desktop`, `chat`, `no_request`; неполный запрос может вернуть `clarification_required`. Обычный вопрос не требует префиксов «Расскажи» или «Объясни».

Jev выбирает типизированные варианты из состояния. Для заметки и текста напоминания код строит токены с идентификаторами и смещениями, модель выбирает начало и конец, а `desktop/core/natural-command.mjs` копирует проверенный непрерывный фрагмент исходной команды. Текст не пересказывается моделью. Сроки и проценты также вычисляет локальный код из исходных кандидатов; Jev выбирает кандидат, не придумывает timestamp или число. Проверяются форма ответа, допустимые метки, вероятности, уверенность и аргументы инструмента. Цитата, отрицание или неоднозначный запрос не являются разрешением на действие.

В production `main.mjs` передаёт семантический интерпретатор. Старый детерминированный парсер сохранён для legacy/offline-вызовов без интерпретатора; он не является автоматическим обходом отказа или сетевой ошибки Jev в основном пути. Gemini отвечает на вопросы без локальной БД, истории и инструментов компьютера.

### Напоминания и уточнение времени

Поддерживаются простые относительные интервалы старого парсера и местные календарные формулировки «сегодня», «завтра», «послезавтра» с точным временем `ЧЧ:ММ`. Прошедшее или несуществующее местное время отвергается. Одна запись не выбирает молча один вариант из составного, исправленного или альтернативного срока.

«Напомни завтра проверить чай» возвращает «Во сколько завтра?» без сохранения записи. Контроллер может хранить одно такое уточнение в памяти с TTL 120000 мс. Следующая команда в этот срок может содержать точное время, например `18:30` или `в 18:30`, при необходимости с одним из трёх поддерживаемых дней. Это узкий ответ на недостающее время: «вечером», «после работы» и другие свободные формулировки не заполняют поле автоматически. Время без даты вне активного уточнения не означает автоматически сегодня или завтра.

Контекст одноразовый, не сохраняется в SQLite и сбрасывается при другом запросе, истечении срока или явной остановке. При успешном уточнении журнал связывает исходный запрос, ответ, первоначальный запуск и вычисленный срок; запись создаётся только после проверки. Напоминания требуют работающего приложения, повторная самостоятельная команда не дедуплицируется.

## Исполнители Windows

`scripts/windows-desktop/controller.mjs` получает свежие наблюдения через `WindowsBridge` и нативный helper. Win32/UI Automation дают окна, доступные элементы и операции. Jev выбирает из актуальных кандидатов; код проверяет цель, допустимость действия и соответствие receipt запросу. Для чистых оконных команд семантический маршрут может передать ограничение `activate`, `minimize`, `maximize`, `restore` или `close`: тогда выбор не засоряется кнопками и вкладками. Запуск приложений использует проверенные ярлыки меню «Пуск».

В Windows-цикле пороги действия и проверки достижения цели — probability ≥0,80 и confidence ≥0,80. Они не заменяют native evidence. Подтверждённое действие, наблюдаемое изменение и неопределённый исход показываются раздельно; например, отправленная замена текста через ValuePattern не доказывает содержимое поля, если оно не считывалось обратно. Общего анализа изображения экрана и произвольных действий по координатам нет.

`desktop/automation/system-tools.mjs` предоставляет фиксированные инструменты. `native/windows-desktop/SystemVolume.cs` читает и устанавливает абсолютную громкость стандартного мультимедийного устройства через CoreAudio. Успех требует readback того же устройства и совпадения уровня; состояние mute сохраняется. При неизвестном результате автоматического повтора нет. Сворачивание самого Jeff вызывает callback собственного `BrowserWindow`, затем проверяет состояние окна. Оба пути возвращают структурированный receipt; одного `ok` без `verified:true` для `system_completed` недостаточно.

## Приватный Gemini gateway

`server/gateway.mjs` обслуживает `/chat`, `/transcribe` и подключённый WebSocket-маршрут live. Доступ требует bearer-токен. `desktop/providers/gemini.mjs` открывает SSH-туннель через `ssh2` с проверкой SHA-256 fingerprint host key; локальный порт выбирается на loopback. Серверный сервис рассчитан на loopback-доступ, а не публикацию HTTP-порта.

Сервер использует `JEFF_GATEWAY_TOKEN` и `GEMINI_API_KEY`. Модели по умолчанию задаются отдельно: `GEMINI_MODEL=gemini-3.1-flash-lite`, `GEMINI_TRANSCRIBE_MODEL=gemini-3.5-transcribe`, `GEMINI_LIVE_TRANSCRIBE_MODEL=gemini-3.5-transcribe-live`. Размеры сообщений, аудио, очередей и длительность соединений ограничены. Шлюз не читает SQLite и не имеет инструментов Windows. `gateway.json` содержит параметры подключения и доверенный `hostHash`, но не ключи; отключать проверку fingerprint нельзя.

## Данные, журналы и диагностика

Основная папка данных — `%APPDATA%\Assistant Jeff`:

- `assistant.sqlite` — совместимый Store заметок и напоминаний, без шифрования;
- `windows-voice-settings.json` — настройки основного пути, включая live/batch;
- `gateway.json` и `secrets/*.dpapi` — параметры доступа и секреты DPAPI текущего пользователя;
- `logs/voice` — статусы, финальные транскрипты и метрики без аудиобайтов и промежуточных гипотез.

Если целевой БД ещё нет, `main.mjs` создаёт копию исходной `data/assistant.sqlite` через `VACUUM INTO`, не изменяя оригинал. Существующая целевая БД не перезаписывается. `JEFF_DATA_DIR` задаёт изолированные данные и отключает автоматическое копирование личной БД и секретов. Записи Python и Electron впоследствии не синхронизируются.

`scripts/desktop-lab/journal.mjs` сохраняет JSON/JSONL команд: запросы и ответы Jev, решения, шаги, native receipts, ошибки и время. В исходниках путь по умолчанию — `work/windows-desktop/runs`; для упакованного приложения — `logs/windows` внутри папки данных. Семантический родительский отчёт сохраняет связь с дочерним desktop-запуском и его evidence. Для UI прогресс дочерней задачи связан с родительской, исходные идентификаторы журналов сохраняются. Текст задач и названия окон могут быть личными данными; фильтрация секретов не делает журнал обезличенным.

`clarification_required` означает необходимость уточнения без эффекта; `local_completed` — подтверждённый локальный результат, `system_completed` — проверенный системный receipt. Desktop-причины `goal_verified`, `goal_observed`, `not_verified`, `execution_uncertain` сохраняют различие между подтверждением и неопределённостью. Ошибка озвучки не меняет уже полученный результат задачи. Индикатор настроенного провайдера проверяет локальные ресурсы и конфигурацию, а не успешность следующего облачного запроса.

## Сборка и границы проверки

`npm run windows:build` собирает helper; `npm run prepare:runtime` готовит и проверяет нативные ресурсы. `npm run pack` и `npm run build` создают соответственно распакованное приложение и NSIS x64-установщик в `release`. Python основному пути не нужен. Ключи, личные БД, журналы, модели и сборочные артефакты не входят в Git; доступ к приватным провайдерам настраивается отдельно.

Автоматические тесты, Electron smoke, вызовы реальных API с синтетическим аудио, проверка native fixture и запуск установленного приложения — разные виды доказательств. Голосовые прогоны этой итерации использовали синтетическое аудио; они не подтверждают микрофон пользователя, распознавание имени в комнате, AEC или поведение в шуме. Измерение от конца аудио до финального текста также не является полной задержкой команды: в неё входят окончание речи, Jev, действие, проверка и ответ.
