# Голос и Windows в Assistant Jeff 0.3

## Один рабочий вход

`package.json` версии 0.3.0 использует `scripts/desktop-lab/main.mjs` как основной Electron entrypoint. Название папки историческое: `npm start`, `npm run windows` и `npm run lab` открывают настоящий Windows-режим с голосом. Изолированный WinForms-стенд доступен отдельно через `npm run lab:fixture`; старый интерфейс — через `npm run start:legacy`.

Ручной текст и окончательная транскрипция попадают в один `UnifiedCommands`. Точные заметки/напоминания идут в прежний `Store`, вопросы с префиксом «Объясни», «Расскажи» или «Вопрос:» — в Gemini без desktop-инструментов, остальные задачи — в Windows-цикл Jev. Промежуточный звук или ещё не завершённая фраза не вызывают действий.

## Голосовой цикл

1. Пользователь включает «Ожидать Jarvis» или «Сказать команду». Без этого микрофон выключен.
2. Hey Jarvis определяется локально через ONNX. Кольцевой буфер около 700 мс удерживает начало записи на время срабатывания детектора.
3. После активации локально собирается фраза. Через 2,5 секунды тишины либо по кнопке завершения фрагмент закрывается.
4. Локальный FFmpeg кодирует MP3. Готовый фрагмент отправляется через закрытый Gemini gateway на `/transcribe`, использующий Gemini 3.5. Это пакетная транскрипция: непрерывного WebSocket/WebRTC-распознавания здесь нет.
5. Окончательный текст отображается в поле. Настройка «Выполнять после распознавания» определяет, пойдёт ли он сразу в общий исполнитель или останется для проверки.
6. При включённой озвучке локальный нативный Piper произносит результат голосом `ru_RU-denis-medium`. После озвучки ожидание может продолжиться; ручная запись завершается как одна сессия.

AssemblyAI не участвует в этом пути. Сигнал активации, озвучка Дениса и автоматическое выполнение переключаются независимо и сохраняются. Голосовой ответ сообщает неподтверждённое или частичное выполнение как таковое; отправка команды исполнителю не считается успехом.

Chromium запрашивает echo cancellation и noise suppression. Это не подтверждение качественного подавления музыки или динамиков. Системное приглушение звука ещё не реализовано. Реальный микрофон, детектор имени в комнате пользователя и AEC в текущей итерации не проверялись.

## Общие данные и журналы

- `%APPDATA%\Assistant Jeff\assistant.sqlite` — существующие заметки и напоминания; используется совместимая схема `Store`. Исходная база не заменяется и не очищается.
- `windows-voice-settings.json` — настройки нового голосового режима. Старые настройки не перезаписываются этими переключателями.
- `logs\voice` в папке приложения — статусы, транскрипция, метрики и связь с `runId`; аудиобайты не журналируются.
- Журнал задач: `work\windows-desktop\runs` при разработке или `logs\windows` в папке данных установленной сборки. Запросы/ответы, действие, receipt, проверки и результат доступны в интерфейсе.

Если пользовательской SQLite ещё нет, исходная `data\assistant.sqlite` копируется через SQLite; оригинал сохраняется. Для изолированных проверок предусмотрен `JEFF_DATA_DIR`, который должен указывать на отдельную тестовую папку. Не направляйте тесты на личную базу.

Ожидание имени не отправляет звук в облако. После активации в Gemini уходит записанная команда. В Windows-задачах Jev получает текст, имена приложений и доступные UIA-факты; общего анализа скриншотов нет. Ключи остаются в защищённом хранилище DPAPI и не включаются в журналы, Git и пакет. Текст заметок, задач и UI-названия не следует считать зашифрованными локальными данными.

## Ресурсы и упаковка

Основные команды из текущего `package.json`:

```powershell
npm.cmd ci
npm.cmd run windows:build
npm.cmd run prepare:runtime
npm.cmd start
npm.cmd test
npm.cmd run pack
npm.cmd run build
```

`windows:build` собирает helper и манифест его ресурсов. `prepare:runtime` не запускает приложение; проверяет готовый helper, модели и hashes, подготавливает нативные ресурсы. Если Piper ещё не установлен, запускает закреплённый `install-voice-runtime.ps1`; отдельно это `npm run voice:install`.

Нужны подготовленные ресурсы:

| Источник при разработке | Содержание |
| --- | --- |
| `models` | `melspectrogram.onnx`, `embedding_model.onnx`, `hey_jarvis_v0.1.onnx` и `download-manifest.json` для проверки hashes |
| `data/tts/piper` | `ru_RU-denis-medium.onnx`, соответствующий `.onnx.json`, `denis-MODEL_CARD.md` |
| `work/windows-desktop/bin` | Native helper, FlaUI/UIA3 DLL, config, manifests и notices |
| `work/voice-runtime/piper` | Нативный Piper x64, библиотеки, phonemizer data, licenses и runtime manifest |
| `work/voice-runtime/ffmpeg` | Настоящий `ffmpeg.exe`, LICENSE и runtime manifest |

Wake-word и Denis веса подготовка сама не скачивает. FFmpeg берётся из уже подготовленного runtime, локального пакета Chocolatey либо из явно переданного пути. Для последнего варианта:

```powershell
powershell -NoProfile -File scripts/prepare-windows-runtime.ps1 -FfmpegPath "C:\tools\ffmpeg\bin\ffmpeg.exe" -FfmpegLicensePath "C:\tools\ffmpeg\LICENSE"
```

Нужен реальный исполняемый файл, не shim пакетного менеджера. Пути в примере заменяются на существующие локальные файлы. Piper загружается из закреплённого официального release; его SHA256 измерен локально и не выдаётся за подпись издателя. Notices и model card включаются вместе с бинарными ресурсами.

`pack` собирает распакованный Windows x64-пакет, `build` — NSIS в `release`; оба сначала вызывают `prepare:runtime`. В `extraResources` входят helper, скрипт чтения меню «Пуск», ONNX wake-модели, Piper, FFmpeg и Denis. Личные базы, ключи, журналы и рабочие записи в пакет не входят. Уже установленная старая версия обновляется только после отдельной установки нового пакета.

## Фактическая проверка и оставшиеся границы

В этой итерации реальный запрос транскрипции MP3 занял **1 966 мс**, отдельный `/chat` — **2 812 мс**. Эти измерения относятся к API, не ко всей цепочке имя → запись → распознавание → действие → голос. Настоящий микрофон и акустическая работа в комнате пока не проверены.

Windows-часть остаётся ограниченной наблюдаемыми окнами и UIA-паттернами, с неизменным порогом 0,80. Раскладка — только установленная English/Russian активного целевого окна. Ввод — явная замена всего поля строкой из `замени текст на «…»`; обратного чтения Value нет, поэтому receipt ввода не подтверждает совпадение значения. Детали: [Windows-исполнитель](windows-desktop.md).

## Проверено 20 сентября 2026 для версии 0.3

- 278 JavaScript-проверок прошли; одна внешняя проверка wake-word oracle пропущена.
- Нативный Windows helper: 45 адресных проверок и 15 сценариев с собственным контролируемым приложением прошли. При отладке выявлен слишком короткий таймаут UIA-мутаций: теперь чтение ограничено 650 мс, один вызов действия — 2000 мс; после него лимит чтения восстанавливается. Неопределённые эффекты не повторяются.
- Исходная команда `открой диспечер задач` проверена через настоящий интерфейс и Jev. Финальный прогон занял 4458 мс и подтвердил уже открытое активное окно (`goal_verified`), без лишнего повторного запуска. Исправлены отсутствие системного приложения в каталоге, чтение идентичности Task Manager без повышения прав и приоритет уже достигнутой цели перед выбором нового действия. Это не измерение холодного запуска Task Manager.
- Реальный renderer, preload, разрешение media, ONNX и AudioWorklet проверены на синтетическом устройстве: получены PCM-фреймы, Stop прекратил захват, фоновых облачных запросов не было. Физический микрофон не использовался.
- Фраза Дениса «Джарвис, открой диспетчер задач» прошла PCM → пауза → MP3 → настоящий Gemini → `открой диспетчер задач.`. В этом тесте автоматические действия были выключены. Распознавание заняло 3570 мс; отдельный более ранний MP3 — 1966 мс. Время ожидания конца живой фразы добавляется отдельно.
- Распакованная сборка 0.3 загрузила интерфейс и native helper; комплектные модели и кодировщик обнаружены. Комплектный Piper реально синтезировал WAV с Denis.
- Полный живой сценарий переключения раскладки и проверка ввода в разных личных приложениях пока не подтверждены. Тест замены в собственном поле прошёл частично, дополнительные сценарии упёрлись в доступность фокуса. Работа настоящего микрофона, произношение имени в комнате, качество AEC и системное приглушение динамиков требуют отдельной проверки/доработки.
