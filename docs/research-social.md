Проверено 19 сентября 2026. Только чтение публичных источников; репозитории не запускались, API моделей не вызывались, видео не просматривались.

## Доступ и полнота

Все пять страниц X вернули 403 через web. Во время первого прохода исследовательский агент не смог открыть встроенный браузер; позднее он был доступен для проверки интерфейса приложения. Публичный X syndication endpoint `https://cdn.syndication.twimg.com/tweet-result?id=<ID>&lang=en&token=0` вернул тексты/метаданные всех пяти постов. Длинные note-tweets там обрезаны. Полный текст трёх длинных постов получен через публичное зеркало `https://api.fxtwitter.com/<author>/status/<ID>`; это вторичный транспорт, поэтому технические выводы ниже сверены с README авторов.

Ответы ветки Moritz целиком получить не удалось: подтверждён заголовок подборки, но не каждый пост внутри треда. У ролика Andy API показывает длительность 48,083 с и доступные MP4; это не означает, что ролик просмотрен или его задержка измерена.

## Репозитории: подтверждено первичными README

### browser-use/jev-ultrafast

[README](https://github.com/browser-use/jev-ultrafast) описывает браузерный агент: DOM → таблица элементов → один запрос Jev для операции и совместимой цели → проверка свежести → исполнение. Свободный текст пишет отдельная малая LLM только для TYPE_TEXT. Модель не выдаёт исполняемый JavaScript/селекторы/команды shell.

Опубликованные 7,073 с Google Flights включают модель, ввод и ожидания, но отсчёт начинается после начального наблюдения. Сравнение — три повтора одной задачи на профиль, не универсальный benchmark. Не поддерживаются frames, shadow roots, canvas, uploads и ряд сложных виджетов. Демо не покупает билет. Практический перенос: ограниченный набор действий, цели только из наблюдения, независимая проверка результата DONE.

### moritzkremb/jev-voice-browser

[README](https://github.com/moritzkremb/jev-voice-browser) — Node ≥20, Web Speech API Chrome/Edge → Node → Jev → Playwright Chromium. **Web Speech отправляет аудио Google**, это не локальная STT. Jev получает частичные транскрипты с debounce 200 мс и параллельные вопросы intent/target/completeness/is-command/destructive. Свободный текст извлекается кодом как буквальные фрагменты, модель лишь выбирает.

Автор указывает ~250–350 мс на ответ Jev и 27/27 integration cases на своей машине. Это опубликованные результаты автора, у нас не повторялись. Для search/type ждёт final или 600 мс тишины; старые запросы отменяет, не более двух одновременно. Снимок ограничен 100 элементами, iframe не видны. Пороговые значения привязаны к jev-1.13.0, переносить их без оценки нельзя. Полезны разделение partial/final, отмена устаревших решений и один action на utterance. Для заметок/напоминаний Assistant Jeff фиксирует действие только после final.

### awlevin/typesafe-computer-use

[README](https://github.com/awlevin/typesafe-computer-use) — **macOS 14+, Python 3.12+**, Apple Vision OCR + Accessibility + AppleScript. Jev выбирает действие, текст создаёт отдельный writer. Приведены 0,13–0,38 с model latency и около 1,5 с end-to-end step; это разные метрики. Windows-адаптера в описанной реализации нет.

Применим подход «локальное наблюдение → ограниченные варианты → исполняющий код», но не готовая Windows-библиотека. У этого проекта сохраняются скриншоты и payload traces; копировать такой режим в приватного помощника без отдельного управления историей не следует.

### droidrun/mobile-jev

[README](https://github.com/droidrun/mobile-jev) — Android через Mobilerun API, TypeSafe и отдельные ключи/услуги. Jev выбирает операцию и наблюдаемую цель; executor проверяет свежесть, а текст копируется из цели дословно. Сам README подчёркивает: DONE не доказывает успех. Демо Uber доходит до выбора оплаты, завершённая поездка/покупка не демонстрируется.

Это архитектурный пример, не Windows-адаптер и не нужная зависимость текущего MVP.

### CUA-S1-FORMS

[Hugging Face model card](https://huggingface.co/cua-ai/cua-s1-forms/blob/main/README.md) указывает 706 048 параметров, 2,8 MB checkpoint, выбор готовых значений/check/click/skip за один проход, MIT для этого артефакта. 99,7% против 83,6% Jev — узкий form-filling eval; часть разницы связана с обученным правилом не менять уже заполненные поля. Англоцентричный словарь; synthetic training и всего 196 решений real-demo eval. Текст не генерирует, пропущенные значения не придумывает.

Есть существенное расхождение источников: [актуальный GitHub README cua-s1](https://github.com/trycua/cua/blob/main/libs/cua-s1/README.md) описывает source-only early research, checkpoint profile без распространённых весов и не устанавливает claims о качестве. HF отдельно публикует checkpoint/model card. Поэтому нельзя считать GitHub source-only релиз доказательством готовой универсальной модели или автоматически распространять лицензию кода на любые будущие веса.

## Архитектурный вывод

Для первой версии: локальный Jarvis → сигнал → потоковая STT → final transcript → Jev выбирает из разрешённых намерений → код валидирует параметры и выполняет → видимый результат/голос. Gemini нужен для свободного ответа или извлечения сложных параметров; Jev не является генератором текста.

Открытие приложения лучше начать с явного каталога разрешённых приложений. Произвольные клики требуют отдельного Windows UI Automation адаптера и наблюдений текущего окна; ни один из рассмотренных демо не даёт готовую проверенную замену. Возможное более позднее браузерное направление — архитектура jev-ultrafast/voice-browser, после отдельной проверки русского, задержки всей цепочки и неверных/устаревших решений.
