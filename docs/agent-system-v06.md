# Агентская система 0.6

Документ фиксирует контракт агентского слоя версии 0.6, собранной и установленной 20 сентября 2026 года. Поддержка любого Windows-сценария не заявляется; конкретные проверки перечислены в README.

## Кто за что отвечает

`AgentCommands` — оркестратор запуска в Electron main. Он не знает конкретных UI-координат и не выполняет модельный текст как программу. Его граница такая:

1. получает одну команду и создаёт новый `LocalToolRegistry` из доступных typed descriptors;
2. отправляет в Gemini список функций с JSON Schema;
3. принимает только структурированный `functionCall`, валидирует имя и аргументы и вызывает локальный descriptor;
4. возвращает модели ограниченный receipt;
5. после каждого результата решает, нужен ли следующий read или финальный `assistant_respond`.

Каждый receipt сохраняет различие между `ok`, `verified`, `effectAttempted`, `effectConfirmed`, `evidence`, `data` и неопределённым исходом. Для effect-инструмента повтор с теми же аргументами не запускается автоматически. После подтверждённого dispatch, который сам по себе не доказывает цель, следующий effect блокируется до нового observation.

Последний ответ модели обязан быть одним вызовом `assistant_respond` со статусом `answer`, `completed`, `clarification` или `incomplete`. Статус `completed` принимает только `evidenceIds` от проверенных вызовов; иначе система возвращает незавершённый результат.

## Контекст разговора

Контекст между запусками хранится только в памяти `AgentCommands`:

- максимум 8 предыдущих ходов;
- максимум 24 KiB после очистки данных, которые привязаны к прошлому наблюдению;
- срок 30 минут;
- `clearContext` полностью удаляет его, в том числе при явной остановке.

Старый ход передаётся модели как справочная фраза и не даёт разрешения на новый эффект. Window/control IDs, snapshot IDs и другие эфемерные ссылки вырезаются или перечитываются в новом запуске. Readable details показывает число ходов и capability snapshot текущей попытки, но не скрытые рассуждения или opaque signatures.

## Gateway-модель

`desktop/providers/gemini.mjs` передаёт в `/agent` только `contents`, `tools` и `context`. `server/agent-model.mjs` проверяет JSON-границу, нормализует function calls и строит Gemini `generateContent` payload. Gateway не владеет локальным registry, SQLite, окнами или native helper: он только выполняет модельный шаг и возвращает кандидат вызова.

По умолчанию агент использует `gemini-3.1-flash-lite`; выбор другого имени делается конфигурацией `JEFF_AGENT_MODEL`. Это не меняет список локальных полномочий. Если модель вернула неизвестную функцию, лишнее поле, невалидную схему или слишком большой payload, вызов отклоняется до executor.

## Локальные data tools

Store-инструменты намеренно похожи на обычный CRUD, но мутация всегда привязана к свежему чтению.

| Объект | Чтение | Изменение | Защита |
| --- | --- | --- | --- |
| Заметки | `notes_search`, `note_get` | `note_create`, `note_update`, `note_delete` | `note_update/delete` требуют `id` и точный `expectedText` из `note_get`; запись перечитывается |
| Напоминания | `reminders_search`, `reminder_get` | `reminder_create`, `reminder_update`, `reminder_delete`, `reminder_complete` | мутация требует `id`, `expectedText` и `expectedDueAt`; доставленное напоминание нельзя молча переносить |
| Время | `clock_now` | `time_resolve` | локальная зона и ISO со смещением; отсутствующий день/час не угадывается |

Например, запрос «измени напоминание про чай на 18:30» сначала получает страницу напоминаний, читает конкретную запись и проверяет оба ожидаемых поля. При изменении записи другим процессом инструмент возвращает `stale_target`, не выполняя замену.

`clock_now` нужен для явного уточнения текущего времени. `time_resolve` принимает относительный или календарный typed-ввод и отвергает несуществующее, прошедшее или неполное местное время. Свободное «вечером» не превращается в скрытый timestamp.

## Windows tools

Базовый `windows-tools.mjs` использует существующий FlaUI/UIA3 helper для списка окон, allowlisted app catalog, оконных операций, системных fallback-путей и ограниченного набора UIA candidates. Его `windows_choose` — optional read-only вызов Jev: он выбирает один уже наблюдаемый action ID для неоднозначной цели. Он не исполняет действие и не генерирует selectors или native arguments.

`winapp-tools.mjs` добавляет отдельный optional adapter к pinned Microsoft `winappCli v0.6.1`. Он превращает UIA tree/search в opaque window/element/action IDs и предлагает только typed `select`, `toggle`, `expand`, `scroll` и `invoke`. Selector/HWND строятся и проверяются кодом; модель получает ID, label и состояние, а не строку CLI. `invoke` сообщает dispatch, затем требует повторного observation; state-changing patterns требуют postcondition readback.

Для обычных editable-полей уже подключён отдельный native text worker. После свежего `windows_observe` `windows_text_fields` читает ограниченные доступные для записи `ValuePattern`-поля одного неминимизированного окна и возвращает обычные значения модели по запросу инструмента. Password/secret-поля, их значения и чувствительный контекст исключаются; фокус не требуется. `windows_text_replace` принимает `snapshotVersion`, `fieldId` и ограниченный literal, заменяет всё поле через `ValuePattern.SetValue` без нажатия клавиш и подтверждает `verified:true` только после точного readback. Идентичность цели привязана к process start, window fingerprint, UIA runtime ID и хешу предыдущего значения; receipt содержит `textLength` и `valueHash`. Stale, смена идентичности или несовпадение значения блокируют продолжение.

Для любого Windows effect применяется один порядок: свежий observation → один action → native receipt → re-observe. `STALE`, `target moved` и `execution_uncertain` не превращаются в автоматический повтор. UIA provider, виртуализированный список, canvas, locked session или отсутствие interactive desktop могут вернуть unavailable; fallback к shell, координатам или произвольному ключу запрещён.

## Голос и финальные эффекты

`VoiceSession` передаёт в AgentCommands только финальный текст. Live PCM16 mono 16 kHz имеет bounded буфер подключения примерно на две секунды; тишина по умолчанию завершает реплику через две секунды. Interim transcript отображается, но не вызывает tool.

Denis остаётся локальной озвучкой результата. Он вызывается после report и не создаёт новый tool call, не включает микрофон и не меняет состояние Windows. Поэтому любой effect относится к финальной команде и receipt, а не к промежуточному аудио или к голосовому ответу.

## Что видно в readable details

`desktop/automation/log-view.mjs` строит bounded view для capabilities, observation/coverage, model decisions, tool calls/receipts, agent responses и количества context turns. Публичное представление не раскрывает скрытые мысли модели и не подменяет receipt текстом «готово». Секретные поля и необработанные подписи не входят в этот view; interim audio hypotheses не являются журналируемым результатом.

## Граница проверки

Подтверждены 631 автоматический тест (1 пропущен), 10 сценариев настоящего Electron main/preload/renderer с подставными внешними зависимостями, 45 native-проверок и 16 Windows-действий на собственном стенде. Реальный API прошёл 8 последовательных CRUD/контекстных сценариев в отдельной SQLite; реальный Chrome восстановлен, громкость прочитана. Live-аудио доведено до одного сохранённого тестового напоминания. Установщик и ресурсы сопоставлены с исходниками, личные базы сохранены. Подробные измерения и неудачные проверки находятся в README.

Transient upstream 429/502/503/504 повторяют только неизменный запрос модели, максимум два раза с паузами 2 и 8 секунд. Локальные инструменты при этом не повторяются. Некорректные аргументы, отсутствие финального `assistant_respond` и неверные evidence IDs возвращаются модели для ограниченного исправления; успешная мутация повторно не выполняется.
