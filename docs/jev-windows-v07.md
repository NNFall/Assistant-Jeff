# Jev управляет Windows: проверка 0.7

Дата: 21 сентября 2026. Основной вход: `scripts/desktop-lab/main.mjs`.

## Исправление архитектуры

В 0.6 основным исполнителем стал общий Gemini tool-calling агент. Jev был необязательным инструментом `windows_choose`. Это расходилось с целью проекта: проверить самостоятельное последовательное управление компьютером именно через Jev.

В 0.7 Jev сначала выбирает маршрут запроса. Для `desktop` каждый следующий шаг выбирает Jev из текущих наблюдений Windows. Gemini не получает desktop-инструменты и не подменяет Jev при ошибке или недостаточной уверенности. Для `memory` и `conversation` сохранён отдельный Gemini-агент только с инструментами заметок, напоминаний и времени. Gemini Transcribe распознаёт речь; Denis озвучивает результат.

```text
Команда → Jev выбирает desktop
  → список окон и системных поверхностей
  → Jev выбирает область → локальное чтение UIA
  → Jev выбирает доступную кнопку → локальный исполнитель
  → проверка результата → новое наблюдение → следующий выбор Jev
```

Это не записанный сценарий для SberBox. Набор кнопок строится из свежего UIA-наблюдения. Панель задач раскрывается по структурным областям: системный трей, Пуск/поиск, приложения. Открытое системное меню становится следующим наблюдаемым окном. Исполняемые ID связывает локальная таблица; модель не назначает backend, HWND, координаты или произвольные аргументы.

## Найденные общие дефекты

1. Из наблюдений выпадали панели задач и системные host-окна. В живой проверке видимые «Быстрые настройки» (`ShellHost.exe`, `ControlCenterWindow`) имели Win32 `IsWindowVisible=false`, хотя UIA и снимок экрана показывали панель. В следующем снимке видимость уже была true, но Win32 EnumWindows всё равно не перечислял меню и основную панель задач; прямые дети UIA desktop их содержали. Поэтому inventory дополняется доверенными shell-корнями UIA, с прежней проверкой пути процесса и идентичности.
2. Действия разных окон конкурировали в одном списке. Внутри выбранной поверхности теперь показываются её действия, переходы к новым системным меню и возврат к списку окон.
3. UIA Invoke не обязательно открывает меню shell-кнопки. Добавлен click по свежему UIA-элементу с hit-test, проверкой владельца и границ.
4. При масштабе 125% геометрия DPI-unaware процесса отличалась от физических координат. Helper включает PerMonitorV2 до обращения к UIA/геометрии; click без подтверждённого пространства физических координат недоступен.
5. Первый частичный снимок преждевременно прекращал ожидание меню. После одного нажатия выполняются ограниченные пассивные перечитывания; повторного нажатия нет.
6. Уже существующее свёрнутое приложение ошибочно могло считаться достигнутой целью. Чтение такого окна больше не выдаёт проверенное выполнение запуска/активации.
7. Запрет повторов мешал последовательности «сверни → восстанови → снова сверни». Подтверждённые действия допускают ограниченный повтор; неизвестный эффект не повторяется.
8. Дочерние журналы давали дубли команд в истории. UI показывает одну родительскую запись с решениями и результатами внутренних шагов.

## Контракт решения и проверки

TypeSafe: `POST https://api.typesafe.ai/v1/systemone`, `model: jev-latest`, один `Choice` `next_step`. Состояние включает исходную команду, наблюдение, кандидатов и восемь последних кратких результатов. Вызовы этого прогона возвращали `jev-1.13.0`.

Для эффекта и завершения нужны вероятность выбранного варианта и confidence не ниже 0,8. До трёх дополнительных чтений допускаются при обоих показателях от 0,2. Исключение не распространяется на нажатия. Максимум — 24 шага / 120 секунд.

Журнал хранит фактический запрос, нормализованный ответ, читаемое действие, вероятность, confidence, задержку и native receipt. Скрытые рассуждения модели не генерируются и не показываются. `step_03` — ключ конкретного текущего варианта; в интерфейсе рядом отображается его полный смысл.

Для точно названного аудиовыхода итог дополнительно проверяется чтением фактического CoreAudio default multimedia endpoint. Сам клик или уверенное `done` не доказывают переключение. Для остальных общих UI-задач различаются проверенные отдельные действия и оценка завершения всей задачи моделью.

## Область проверок

Изолированные автоматические проверки и реальные API-вызовы проверяют разные слои:

- Unit/integration: контракт TypeSafe, выбор маршрута, остановка/повторы/свежесть, привязка ID, иерархия, CoreAudio, журналы и UI.
- Electron smoke: настоящий main/preload/renderer и изолированная SQLite; внешние API и native-эффекты заменены фикстурами. Проверяются заметки, контекст, цепочка Jev и отсутствие Gemini-вызовов в desktop-ветке.
- Живые API-пробы: реальные ответы Jev на синтетические наблюдения; они сами по себе не подтверждают управление Windows.
- Живой Windows-прогон: реальный UIA, реальные решения Jev, физические действия и независимое чтение аудиовыхода. Его итог фиксируется ниже отдельно.

## Ограничения

Это UIA-контур, а не универсальное зрение. Canvas без accessibility, виртуализированные/скрытые элементы и окна повышенных прав могут быть недоступны. Частичный снимок не считается полным обзором компьютера. OCR/vision и произвольный ввод текста в новую desktop-сессию не подключены. Старый winapp-адаптер сохранён в коде/runtime, но не является вторым исполнителем этого цикла.

Gemini остаётся в распознавании речи, разговоре и работе с данными. Перенос свободного разбора текста заметок/напоминаний на Jev не заявляется этой версией.

## Результат живого прогона и поставки

Автоматические проверки: **718 passed, 2 skipped, 0 failed** (`npm test`, 720 тестов с учётом вложенных). Пропущены опциональные live CoreAudio и Python wake-word oracle. CoreAudio отдельно проверен живым чтением в native-проверке; микрофон и wake-word в этом изменении не перенастраивались. Electron smoke: **13/13**, шесть команд — шесть записей истории, ноль вызовов внешней сети/native-действий/микрофона в изолированном стенде.

Реальный Windows-прогон `1790020133846-eb8277ca-b8eb-4b46-91a4-f0f8416d4125`, команда **«Открой выбор аудиовыхода в быстрых настройках Windows»**:

Весь прогон: 16 949 мс, **итог неуспешный (`low_confidence`)**, все девять запросов — `jev-1.13.0`. Gemini в desktop-цепочке не использовался. Между чтениями popup потерял активность и исчез. Пользователь подтвердил, что одновременно использовал мышь/клавиатуру; поэтому этот прогон не подтверждает надёжность всей последовательности. Причина каждого конкретного закрытия меню отдельно не установлена. После подтверждения параллельного ввода дальнейшие live-нажатия остановлены.

SberBox уже был выбран в CoreAudio до последнего прогона. В журнале нет выбора этого устройства данным циклом — **смена аудиовыхода не приписывается Jev**. После добавления явного проверенного `goalState` отдельный read-only API-запрос «Переключи аудиовыход на SberBox» дал `done`, P=0,99, confidence=0,98, 872 мс, без действий. Полное прохождение «от закрытого меню до смены устройства» остаётся отдельной ручной проверкой в спокойном состоянии рабочего стола.

## Как проверить в приложении

Введите **«Открой выбор аудиовыхода в быстрых настройках Windows»** и нажмите **«Выполнить»**. Во время прогона не используйте мышь и клавиатуру: это тот же рабочий стол, где действует помощник. Кнопка остановки остаётся доступна. Затем отдельно проверьте **«Переключи аудиовыход на SberBox»**; если устройство уже выбрано, ожидается отсутствие лишних нажатий.

Сверху указаны роли моделей; карточка результата показывает исполнителя. В «Подробнее» и истории — отдельные шаги, исходы, уверенность, время и технический обмен. `Нужна проверка`/низкая уверенность не означает успех. Открытие корня меню без списка устройств не считается выполненным переключением.

## Сборка и установка

`npm run build` завершился успешно. В скрипте подготовки явно загружается полный `Microsoft.PowerShell.Utility`: в Windows PowerShell, запущенном из npm, автоимпорт не предоставлял `Get-FileHash`. Проверка хешей ресурсов сохранена.

Установщик `Assistant Jeff Setup 0.7.0.exe` — 305 107 980 байт, silent installation завершилась кодом 0. Установлен `C:\Users\User\AppData\Local\Programs\Assistant Jeff\Assistant Jeff.exe`, ProductVersion `0.7.0.0`. SHA-256 установленного native helper совпал с проверенной сборкой.

Диагностика распакованной и установленной версии завершилась кодом 0: version `0.7.0`, runtime `ok: true`, доступны Denis, wake-модели и encoder, прочитаны 13 окон, микрофон не активирован. Это были изолированные папки без облачных ключей: `gemini/live: false` в этих diagnostic JSON не является результатом проверки облачной авторизации основной пользовательской установки.

После установки хеши обеих существовавших SQLite-баз и репозиторного settings.json совпали с исходными. Тестовые заметки создавались только в отдельных smoke-папках. Последний реальный неполный desktop-прогон скопирован в пользовательский журнал, чтобы его можно было открыть через историю приложения.
