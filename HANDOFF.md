## Что уже реализовано

Приложение написано для пользователя на Python, не просто установлено чужое готовое приложение. Веса нейросетей готовые, мы их не обучали. WritHer был архитектурным референсом, его исходники не копировались.

Конвейер: микрофон -> openWakeWord ONNX -> сигнал -> запись команды с WebRTC VAD -> faster-whisper multilingual small, CPU INT8, четыре потока, beam_size=3 -> детерминированный Python-парсер -> SQLite -> Windows SAPI (Irina).

- Tkinter-окно на русском, трей, настройки, выбор микрофона, запуск без консоли.
- Имена: Hey Jarvis, Alexa, Hey Mycroft, Hey Rhasspy. Произвольная строка имени не заменяет обучение модели.
- Заметки, таймеры, относительные напоминания; обычные русские числа и полтора/полторы.
- Примеры: «Запиши заметку купить молоко», «Поставь таймер на две минуты», «Напомни через десять минут проверить чай».
- SQLite сохраняет данные между запусками, уведомление + звук + TTS. Напоминание ожидает явного подтверждения в интерфейсе.
- После wake-word другие приложения приглушаются до 15% исходного уровня и восстанавливаются. Это **не AEC**; до активации YouTube может мешать.
- Сырые записи микрофона не сохраняются и никуда не отправляются. Рабочие модели локальные, HF_HUB_OFFLINE=1.
- Обычный запуск с выключенным микрофоном; `--background` включает микрофон и запускает в трее. Автозапуск только явным обычным ярлыком Startup, не скрытыми задачами/службами.
- GPU не используется. Whisper загружен в память при работе голосового цикла, но не распознаёт всё непрерывно.
- Нет LLM, Jev, облачной STT/TTS, погоды, произвольного управления ПК, календарных напоминаний, настоящего AEC или голосовой идентификации владельца.

Ревью уже исправило: остановку захвата при продолжающемся STT, позднее открытие микрофона после отмены загрузки, откат частичного ducking, остановку polling после SQLite-ошибки, потерю start после stop, TTS при выключенном микрофоне, устаревшие очереди напоминаний. Не откатывать эти исправления.

### Будущая интеграция

Пользователь хочет поэкспериментировать с Jev от TypeSafe. Возможная роль: типизированный выбор намерения/инструмента после STT. Jev не заменяет микрофон, wake-word, STT, выполнение действий и TTS. Сначала выяснить актуальный API/SDK, доступ аккаунта, цены, формат результата, задержку и ограничения. Не выдумывать endpoint и не отправлять записи/заметки/секреты для тестирования без нужного разрешения.

Сохранить работающий локальный путь как fallback. Проверять аргументы инструментов; не выполнять shell из произвольной речи. Опасные действия потребуют подтверждения. Для простых заметок/напоминаний нынешний парсер остаётся полезным эталоном. Отдельно сравнить быстрый STT и AEC, не смешивая сразу несколько крупных изменений.
