# Jev: реальный тест управления окнами Windows

20 сентября 2026, `jev-1.13.0` через `jev-latest`. Пользователь разрешил
тестовые API-запросы и действия «Сверни Хром и закрой HAPP».

## Что действительно проверено

Модель получает текст команды, названия Chrome/HAPP, состояние окон и историю
подтверждённых действий. Она сама выбирает следующий типизированный шаг.
Локальный исполнитель применяет Windows API и заново наблюдает окна.
Скриншоты, содержимое вкладок, названия страниц и личные записи модели не передаются.

Это ограниченный тест управления окнами через Win32, **не** универсальный
визуальный агент, не поиск кнопок UI Automation и не управление произвольным
содержимым приложений. Новая вкладка намеренно вне возможностей этого стенда.

Успешный реальный запуск:

| Шаг | Запрос Jev | Выполнение + проверка Windows | Вероятность выбора |
|---|---:|---:|---:|
| Свернуть Chrome | 872 мс | 347 мс | 94% |
| Закрыть окно HAPP | 260 мс | 372 мс | 96% |
| Выбрать завершение | 309 мс | — | 92% |

Цикл решений и действий: **2168 мс**. Отдельно до него: запуск вспомогательного
процесса 604 мс, первое наблюдение 443 мс. Расшифровка речи и VAD сюда не входят.
Это один запуск на данном компьютере, а не p95 сервиса.

Windows подтвердил сворачивание Chrome и отсутствие видимого окна HAPP.
Пользователь затем подтвердил: «теперь свернулся и хап закрылся».
HAPP вернул результат `window_closed_process_running`: закрыто окно, процесс
продолжает работу. Это не принудительное завершение приложения или VPN-службы.

## Подбор инструкции и ограничения результатов

Первый синтетический прогон выбрал правильные top-choices 8/8, но четыре действия
не прошли пороги. После сокращения перегруженной инструкции и добавления русских
значений «свернуть»/«закрыть окно» прошли 8/8 без понижения порогов.
Первый реальный прогон свернул Chrome, но остановился перед HAPP: вероятность
правильного выбора была 87% при требовании 90%.

Затем из кандидатов исключены уже выполненные операции и сворачивание уже
свёрнутых окон; список окон стабилизирован независимо от Z-order. После этого
полный реальный сценарий прошёл при прежнем пороге 90%.
**Позже по прямой просьбе пользователя порог вероятности изменён на 85%.**
Дополнительный порог `confidence` остался 80%. Эти числа — настройки стенда,
не гарантия фактической точности. Проверки свежести окна и разрешённых операций
действуют независимо от вероятностей.

В промежуточной дополнительной серии один ответ на отрицательный/цитируемый
запрос был отклонён валидатором как `DESKTOP_RESPONSE`; действий не было.
Сырой ответ того запроса не сохранился, причина не установлена. Runner теперь
сохраняет ограниченный диагностический ответ для таких ошибок на синтетических
fixtures. Проверки формата не ослаблялись.

Последняя серия после правок: **10/10** ожидаемых результатов, включая отрицание,
закрытие уже свёрнутого HAPP, отказ на новую вкладку и два неоднозначных окна Chrome.
HTTP roundtrip: минимум 266 мс, медиана **342,5 мс**, максимум 1000 мс.
Первый запрос серии обычно медленнее последующих. `done` и `unsupported` не вызывают
действий; их низкая уверенность не выдаётся за разрешение действовать.
Маленький набор частично использовался для улучшения инструкции: это smoke/regression,
не независимая оценка качества на произвольных русских командах.

## Воспроизведение

Из корня проекта, Windows:

```powershell
# Только локальное наблюдение; без ключа, сети и действий.
node scripts/test-desktop-jev.mjs --snapshot

# Реальные платные запросы Jev, синтетическое состояние, никаких действий в ОС.
node scripts/test-desktop-jev.mjs --benchmark

# ДЕЙСТВИТЕЛЬНО свернуть Chrome и закрыть окно HAPP.
# Требует ровно одно наблюдаемое окно каждого приложения.
node scripts/test-desktop-jev.mjs --execute
```

Ключ: переменная `TYPESAFE_API_KEY` или локальный защищённый
`data/secrets/typesafe.dpapi`. В логах и Git ключа нет.
Отчёты: `work/desktop-jev-benchmark.json`, `work/desktop-jev-execution.json`.
Синтетический benchmark не закрывает Chrome и не сворачивает HAPP: это варианты
для проверки выбора. Native executor разрешает только Chrome/minimize и HAPP/close,
сверяет executable, HWND, PID и время запуска процесса перед действием.
Команды shell, произвольные координаты, force kill и повтор неуспешного действия
не предоставляются модели.

Код проверен независимым Antigravity Worker (analysis,
job `2436555d-8598-4bf2-bb9c-eaa3bca2cc82`): блокирующих замечаний не выявлено.
Рекомендация по обработке ошибки stdin учтена. Финальная правка порога и
диагностического benchmark проверена локальными тестами после ревью.

Установленное приложение 0.2.0 не пересобиралось: это самостоятельный тестовый
стенд, не новая кнопка и не новый голосовой режим в основном интерфейсе.

Источники API: [TypeSafe](https://docs.typesafe.ai/api),
[Choice](https://docs.typesafe.ai/primitives/choice),
[function calling](https://docs.typesafe.ai/cookbooks/function_calling).
