# Реальное управление Windows

Основное окно версии 0.3 (`npm start`, `npm run windows` или `npm run lab`) работает с настоящими приложениями и объединяет ручные команды с голосом, заметками и напоминаниями. Белое тестовое окно не запускается. Старый интерфейс сохранён через `npm run start:legacy`; [голосовой путь 0.3](voice-windows-v03.md) использует локальное Hey Jarvis, MP3 → Gemini 3.5 и нативный голос Дениса.

## Запуск и использование

```powershell
npm run windows:build
npm run prepare:runtime
npm start
```

Введите задачу и нажмите «Выполнить». Примеры: «Открой Steam», «Сверни Google Chrome», «Разверни Яндекс Музыку на весь экран». «Журнал» показывает сохранённые сессии; папка — `work/windows-desktop/runs` в исходниках либо `%APPDATA%/Assistant Jeff/logs/windows` в установленной сборке. Кнопка открытия папки выбирает текущий путь автоматически.

Есть управление уже открытыми окнами, выбор вкладок/элементов, вызов доступных кнопок, переключателей и раскрывающихся списков через UI Automation. Запуск установленной программы использует каталог ярлыков меню «Пуск»: выбирается известный локальный EXE без дополнительных аргументов. UWP, ссылки-протоколы и программы, требующие аргументов запуска, этим каталогом не покрываются.

Модель не получает скриншоты, не генерирует shell-код, координаты или произвольный текст. Работа с графическими холстами и элементы без доступных UIA-паттернов требуют дополнительных инструментов. Недоступная кнопка или уверенность ниже порога могут остановить задачу. Это реальный исполнитель с определёнными инструментами, не обещание выполнения любой задачи в любом приложении.

Добавлены ограниченные операции ввода. `set_keyboard_language` выбирает только установленную English/Russian активного целевого окна. `replace_text` принимает явную ограниченную строку из команды `замени текст на «…»` и заменяет **всё значение** уже сфокусированного writable ValuePattern-поля. Это не дописывание и не эмуляция клавиатуры; Value обратно не читается, поэтому receipt остаётся непроверенным и не доказывает введённый текст. Если пользователь явно назвал приложение для раскладки или замены, его активация может быть необходимым шагом. Общая команда для текущего поля не разрешает выбрать другое приложение. Обычные UIA select/invoke несвёрнутого окна не требуют перевода фокуса.

Локальные заметки и напоминания используют прежний `Store` и базу в `%APPDATA%/Assistant Jeff`; существующие записи сохраняются. Вопросы с префиксами «Объясни», «Расскажи», «Вопрос:» идут в Gemini без инструментов управления. Голосовой ввод после 2,5 секунды тишины поступает в тот же маршрутизатор; AssemblyAI в новом пути не используется.

## Цикл и свидетельства

1. Win32 перечисляет окна текущей сессии. Снимок хранит идентичность окна и его состояние.
2. Jev выбирает окно для осмотра либо установленное приложение для запуска. После осмотра доступны действия выбранного окна и его UIA-контролы; перейти к другому окну можно новым осмотром.
3. Перед эффектом перечитывается Windows-состояние, проверяются версия, идентичность процесса/окна/элемента и допустимая операция.
4. Исполнитель проверяет фактическое состояние после эффекта. Jev получает новое наблюдение и историю, выбирает следующий шаг либо завершение.

Порог **P ≥ 0,80 и confidence ≥ 0,80** сохранён. Для завершения дополнительно требуется ответ `goal_status=achieved` с тем же порогом. Это отдельный вопрос той же модели, а не независимый эксперт. Ранние шаги составной команды подтверждаются историей; итоговое состояние может намеренно заменять раннее («покажи, затем сверни»).

Уже удовлетворённая наблюдаемая цель проверяется до выбора нового действия: видимое несвёрнутое активное окно может удовлетворять «открой» без повторного осмотра. Если окно уже было успешно активировано с `window_active`, последующий возврат фокуса в Jeff сам по себе не отменяет разовое открытие, пока то же окно остаётся видимым и несвёрнутым. Это не ослабляет проверку конечного состояния для «сверни», «разверни», раскладки и содержимого поля.

`goal_verified` означает: Jev оценил цель по наблюдаемым данным, эффекты в истории имеют проверяемые native-постусловия. `goal_observed` означает: есть лишь наблюдаемое изменение UI, и Jev считает цель достигнутой. Отправленное нажатие само по себе не доказывает успех. Сбой/усечение наблюдения после Invoke даёт неизвестный результат. Автоматического повтора действия с неизвестным исходом нет.

«Стоп» отменяет дальнейшую работу и запросы; уже выполненное действие не отменяется. Прерывание в момент эффекта отмечается `executionUncertain`. После закрытия приложения незавершённая запись журнала обозначается как прерванная и не воспроизводится.

## Журнал и границы

В JSONL до эффекта записываются команда, наблюдение, кандидаты, точный запрос к Jev, допустимый ответ/распределения, выбор, проверка свежести, native-запрос и receipt, время, ошибки и итог. Итоговый JSON записывается атомарно. Некорректный структурированный ответ сохраняется только в безопасной проекции известных полей с причиной отказа. Небольшая погрешность суммы вероятностей API допускается в пределах ±0,015; отдельные значения не пересчитываются вверх и порог 0,80 не меняется. Пароли, API-ключи и заголовки авторизации не журналируются. Названия окон и контролов могут содержать личные сведения, поэтому журналы остаются локальными и исключены из Git. Во время задачи эти названия передаются TypeSafe; фоновой облачной отправки нет.

Закрытие окна выполняется штатным WM_CLOSE, без завершения процесса. Скрытие в трей отмечается отдельно от уничтожения окна. Чувствительные/служебные приложения и поля паролей исключены; удаление, отправка сообщений, покупки и другие рискованные кнопки не предоставляются этому экспериментальному исполнителю.

Обход UIA ограничен выбранным приложением, числом элементов, глубиной и временем. Частичные наблюдения явно помечаются; порядок вкладок вычисляется по расположению, с отдельным указанием неполного покрытия. Команда окну проверяет версию именно его идентичности, заголовка и состояния: анимация содержимого не мешает сворачиванию. Действия UIA и проверка завершения используют полную версию снимка, поэтому изменение интерфейса может вызвать безопасное повторное наблюдение. Повышенные приложения могут быть недоступны обычному процессу.

## Проверки

`npm test` — автоматические проверки без личных приложений и внешнего API. Нативные механизмы отдельно проверяются на контролируемом fixture. Старый fixture запускается только через `npm run lab:fixture`; `scripts/test-desktop-lab-ui.mjs` привязан к этому отдельному entrypoint.

Живой интеграционный тест требует явных параметров и выполняет только переданную команду:

```powershell
node_modules/electron/dist/electron.exe scripts/test-windows-desktop-ui.mjs --live --windows-smoke --command "Открой Steam."
```

Он проверяет собственные renderer/IPC, настоящий Jev, нативный backend и сохранение журнала. Результаты сохраняются в `work/windows-desktop/ui-smoke-*`; ошибки и слабые ответы не удаляются. Общее время включает локальное чтение Windows и каталога программ, а не только задержку модели.

### Историческая проверка Windows-цикла 20 сентября 2026

Эти результаты относятся к отдельным предыдущим прогонам Windows-цикла. Они не являются проверкой новой голосовой цепочки 0.3 или текущей установленной сборки. Актуальные границы голосовой проверки перечислены в [описании 0.3](voice-windows-v03.md).

- 171 автоматический JavaScript-тест прошёл, один внешний wake-word oracle пропущен. Нативные проверки: 23 адресных и 15 интеграционных сценариев с отдельным контролируемым fixture; команды воспроизведения — в `native/windows-desktop/README.md`.
- Настоящий Jev активировал Steam за 3,03 с и выполнил «покажи Google Chrome, затем сверни Google Chrome» за 5,27 с в ранних прогонах. После добавления каталога приложений, полноценного обхода UIA и версии конкретного окна финальное «сверни Steam» выполнено за 13,50 с; это не обещание одинаковой задержки для всех команд. Три вызова модели в этом прогоне заняли 1,25 / 1,08 / 0,99 с, остальное — локальная работа и проверки.
- WinRAR запущен из обнаруженного каталога с подтверждённым PID. Составное «открой, затем закрой» остановилось на неоднозначности окна лицензии. Отдельное «закрой WinRAR» завершилось с `window_absent` за 6,01 с. Успех запуска и последующего отдельного закрытия не выдаётся за успех исходной цепочки.
- «Покажи Steam, затем сверни Steam»: один прогон обнаружил повторные stale-проверки из-за меняющегося UIA; это устранено версией конкретного окна. Следующий остановился с `foreground_not_granted`: Windows не разрешила перевод фокуса. Отправка запроса активации не отмечена успехом.
- Реальный Яндекс теперь отдаёт TabItem; native Select подтвердил переключение вкладки. Однако запрос «первая вкладка ВКонтакте» выбрал вкладку **VK ID**, а итоговый ответ модели не подтвердил цель (`goal_not_verified`). Сценарий семантически не пройден, даже при успешном механическом переключении. Названия и порядок UIA недостаточны для обещания правильной идентификации любого сайта.

Все исходные неудачные прогоны сохранены локально. Это управляемый первый вариант реального desktop-цикла; универсальность управления, низкая задержка любых задач и надёжное понимание всех вкладок не подтверждены.
